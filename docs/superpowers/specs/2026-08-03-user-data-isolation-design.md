# 用户数据隔离设计

## 目标

登录启用后，持仓、自选股、研究记录、上传研报和“问 AI”对话按登录用户独立存储。管理员与普通用户遵循同一隔离规则，只能访问自己的数据。

## 数据目录

数据根目录继续由 `VR_DATA_DIR` 控制，默认 `~/.vibe-research/`：

```text
~/.vibe-research/
├── users/
│   └── <sha256(username) 前 16 位>/
│       ├── identity.json
│       ├── portfolio.json
│       ├── watchlist.json
│       ├── notes.json
│       ├── chats/
│       │   └── <sha256(scope)>.json
│       └── reports/
│           ├── index.json
│           └── files/
└── legacy/
```

目录名使用用户名哈希，不直接拼接用户名，避免路径穿越、特殊字符和不同文件系统编码问题。`identity.json` 仅保存用户名、角色和首次创建时间，不保存密码或登录令牌。

## 当前用户解析

- 登录 Cookie 校验成功后，中间件把 `{username, role}` 写入 `request.state.user`。
- 登录认证启用时，所有私有数据端点必须存在 `request.state.user`。
- `VR_API_KEY` 仍可用于公共行情、AI 和运维类 API，但不能单独访问任何用户私有数据。
- 登录认证未配置时，为兼容本地单用户使用，私有数据映射到固定用户 `_local`。
- 用户目录解析集中在一个模块中，业务模块不得自行拼接用户名路径。

## 服务端存储

### 持仓

现有 `portfolio.py` 从模块级固定文件改为显式接收用户目录或用户存储对象。持仓、已清仓记录和刷新操作只读写当前用户的 `portfolio.json`。后台定时刷新枚举已创建的用户目录，逐用户刷新并隔离错误，不能因一个用户数据损坏影响其他用户。

### 自选股

新增用户级自选股 API，服务端保存去重后的股票代码数组。限制最大数量并校验代码格式。前端页面和资讯关注列表统一从 API 读取，不再以全局 `localStorage` 为主数据。

### 研究记录

新增研究记录 CRUD API，保存标题、正文、来源、创建时间和稳定 ID。设置单条大小和总条数上限。`Notes` 页面以及“保存研究记录”入口改为服务端调用。

### 研报

`myreports.py` 的索引与文件目录从全局常量改为当前用户的 `reports/`。文件下载和删除先在当前用户索引中查找，禁止通过报告 ID 跨用户读取。文件保存在 `reports/files/`，索引原子写入。

### 问 AI 对话

新增对话 API，以现有 `pathname + scopeKey` 作为逻辑 scope，文件名使用 scope 哈希。每个文件保存 scope、消息和更新时间。服务端沿用前端当前的完整轮次过滤与消息数量上限，并增加请求体大小限制。前端 `AskAiButton` 加载、增量保存和清空均走当前用户 API。

## 前端状态与缓存

- `AuthContext` 提供稳定的当前用户名。
- 用户私有数据不再写入无用户前缀的 `localStorage` 键。
- 为减少页面闪烁可保留内存缓存；如保留持久缓存，键必须包含用户目录 ID，并在退出登录时清理当前内存状态。
- AI 服务商配置、后端访问密钥和主题偏好不在本次迁移范围内，继续作为浏览器设备级配置。

## API 边界

新增或调整以下私有接口：

```text
GET/PUT          /api/watchlist
GET/POST/DELETE  /api/notes
GET/PUT/DELETE   /api/chats/{scope}
GET/POST/DELETE  /api/portfolio/...
GET/POST/DELETE  /api/myreports/...
```

所有响应不接受客户端传入 username；用户身份只能来自已验证的服务端会话。由此避免用户修改请求参数读取他人数据。

## 并发与安全

- 每个用户、每类数据使用独立锁；不同用户之间不互相阻塞。
- JSON 使用临时文件加 `os.replace` 原子写入。
- 所有文件路径必须由可信根目录和服务端生成的哈希组成。
- Cookie 过期、用户被删除或角色变化后，私有请求返回 401。
- 不在日志、响应或前端状态中暴露其他用户名、目录名或数据计数。

## 旧数据迁移

- 不自动把现有共享数据归给第一个登录用户。
- 旧的全局 `portfolio.json`、`myreports/` 和浏览器无前缀数据保留，不在正常请求中读取。
- 提供显式迁移命令 `python3 migrate_user_data.py --to-user <username>`，执行前验证目标用户存在，默认仅复制并生成迁移报告；使用 `--move` 才移动原文件。
- 浏览器旧自选股、研究记录和问 AI 内容无法由服务器迁移。前端提供一次性“导入此浏览器旧数据到当前账号”动作，必须由用户主动确认。

## 测试与验收

- 两个测试用户写入同类数据后，只能读取各自内容。
- 用户 A 的持仓、报告 ID、笔记 ID 或对话 scope 不能被用户 B 读取或删除。
- 仅持有 `VR_API_KEY` 的请求不能访问私有端点。
- `_local` 兼容模式在未配置登录时仍可工作。
- 并发写入不会产生损坏 JSON 或跨用户覆盖。
- 前端登录切换后不会显示上一个用户的自选、笔记或对话。
- 后端全量测试、前端测试和生产构建通过。
